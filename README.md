# 钥匙 / 工具 / 标识牌 借用登记与归还确认系统

本系统部署在本机（Windows），后台服务监听 **端口 10800**，借用人通过手机微信扫描后台生成的二维码即可在线登记借用信息。

> **v1.5.1 更新（数据安全加固）**：④ **单实例保护**——同一份 `data` 目录同时只能有一个服务实例运行，第二个实例会**明确拒绝启动**（实测两个实例同写会静默丢记录）；⑤ **第二轮防丢加固**——外部把数据文件**删除 / 清空 / 改小 / 截断**时一律「隔离留证（`data/quarantine/`）+ 从 `.bak` 自动恢复 + 告警」，无法恢复时返回 **503 明确报错，绝不清空历史**；备份文件改为**成对原子落地**（json+csv 同一序号，失败零残留）；还原接口校验加严（伪造状态/畸形物品项一律 400，一个字节都不写）；数量非法（非 1-999 整数）或单笔超 20 件物品**直接报错**，不再静默改值或丢弃。

> **v1.5 更新（2026-10）**：① **修复借用记录丢失问题**——数据读取失败不再被当成「空数据」（这正是过去记录被整体覆盖的根因），并给每个数据文件加 `.bak` 快照与坏文件隔离目录，损坏时自动恢复或明确报错，绝不再静默清空；② 新增管理员「🧾 操作日志」页——按天记录登录、借用、确认、归还、修改、删除、库存与用户管理、导出、备份/还原等关键操作，可按成员/类型/时间/关键词筛选、分页与导出 CSV（保留 180 天）；③ 新增「⏰ 自动备份」——默认**每周三 14:00** 自动备份数据库（JSON）并导出借用记录（CSV）到 `data/backups/`，保留最近 12 次，错过时间下次启动自动补做，时间与份数可在「数据导出」页修改。详见文末「八、更新记录」。

> **v1.4 更新**：新增「借用人确认归还」留档功能——借用人扫码查询状态时，可在「借用中」状态下点「确认已归还」声明已归还（可填备注、**可选拍照**作为归还凭证），该声明会记录在案并提醒运行人员；最终「已归还」状态仍由运行人员在后台点「归还确认」确定。工作台借用目录/详情/历史归档均会展示借用人归还声明，CSV 导出新增相应列。详见文末「八、更新记录」。

> **v1.3 更新**：借用登记新增「借用原因」「备注」字段——登记页在借用物品前填写借用原因、提交前填写备注；后台借用目录、历史归档、记录详情、借用人与运行人员的查询页均可查看；CSV 导出新增借用原因、借用人备注、运行人员备注、取消原因等列；运行人员修改记录时也可编辑借用原因与备注。详见文末「八、更新记录」。

## 一、启动方法

### 方式一：双击启动（推荐）
双击项目目录下的 **`start.bat`** 即可启动服务。

### 方式二：命令行启动
```bash
cd "D:\DSH\Key Borrow-Register System"
npm start
```

> **Windows 上推荐用脚本后台静默运行（无黑窗口）**：双击 `start.bat` 后台启动并自动打开浏览器（脚本会自动检测 Node.js 是否安装、端口 10800 是否空闲，失败会给出中文提示并可在 `server-err.log` 查看原因）；停止服务双击 `停止服务.bat`；启动异常先双击 `环境自检.bat` 一键排查。命令行方式 `npm start` 用于调试。

启动成功后，控制台会显示：

```
本机访问:   http://localhost:10800
局域网访问: http://192.168.x.x:10800   （手机微信扫码用）
```

> 首次使用若提示缺少依赖，先在项目目录执行 `npm install` 一次。

## 三、使用流程

0. **（推荐）导入物品库存**：管理员/运行人员登录工作台 → 「📦 物品管理」→「⬇ 下载导入模板」→ 用 Excel/WPS 填写（物品类型/名称/数量）→ 另存为 **CSV UTF-8** →「📥 导入库存 CSV」。导入后，借用人登记时名称框会**自动联想**库存物品，**被借完的物品不可选**；库存不足提交会被拦截。
1. **管理员/运行人员登录工作台** → 进入「借用二维码」页 → 将二维码打印或展示在值班处。
2. **借用人**用手机微信扫码 → 打开「借用登记」页 → 填写姓名、**借用原因**（必填）、**手写签字**、借用物品（可点「＋ 添加物品」一次登记多件物品，每件含类型/名称/数量）、借用时间（默认当前时间，可改）、计划归还时间（自动为借用时间 +8 小时，可改）、**备注（选填）** → 提交。
3. **运行人员**在「借用目录 → 待确认」中查看申请，可**修改**信息，确认无误后点 **「✔ 确认借用」**，记录留下 **确认标志**（确认人 + 确认时间），物品放行。
4. **归还**：借用人归还后，可先在「归还状态查询」页点 **「确认已归还」** 留档（可选拍照、填备注，非强制）；运行人员在「借用中」列表看到「🙋 借用人已声明归还」提示后，点 **「↩ 归还确认」** 完成最终确认 → 记录**自动归档**，不再显示在借用目录。
5. **超期提醒**：到达计划归还时间仍未归还，系统会以**红色高亮**标注，并在工作台顶部弹出 **🚨 超期提醒横幅**，同时向管理员与运行人员发出浏览器通知。

## 四、手机扫码访问（重要）

手机要能访问本机服务，需满足：

1. **同一局域网**：手机与本机连接同一 WiFi / 网段。
2. **防火墙放行端口 10800**：在 **管理员 PowerShell** 中执行一次以下命令：
   ```powershell
   netsh advfirewall firewall add rule name="借用登记系统10800" dir=in action=allow protocol=TCP localport=10800
   ```
   （如需取消放行：`netsh advfirewall firewall delete rule name="借用登记系统10800"`）
3. 用手机浏览器测试访问：`http://<本机局域网IP>:10800/borrow`，能打开即表示手机可访问。

> 二维码默认使用自动检测到的本机局域网 IP 生成；若使用了路由器端口映射 / 内网穿透 / DDNS，可在二维码页的「访问地址」框中填写对外地址后重新生成。

## 五、数据与导出

- 数据保存在项目目录 **`data/`** 文件夹（`users.json` 账号、`borrows.json` 借用记录、`inventory.json` 库存），**重启/关机不丢失**。备份时直接复制该文件夹即可。
- 工作台「数据导出」页可导出 **全部 / 借用中 / 归档** 三类 CSV 文件（UTF-8 带 BOM），Excel / WPS 直接打开正常显示中文。
- 导出字段：借用单号、借用人、借用原因、物品清单、借用时间、计划归还时间、实际归还时间、状态、确认人、确认时间、归还人、**借用人声明归还、借用人归还备注、归还照片**、是否超期、借用人备注、运行人员备注、取消原因、创建时间。
- **管理员一键备份与还原**：「数据导出」页的「💾 备份全部数据」可下载包含账号、借用记录、库存的 JSON 备份文件；需要恢复时点击「📥 还原数据」选择该备份文件即可一键还原（仅管理员），**还原前系统会自动把当前数据备份到 `data/restore-backup-时间戳/` 目录**，操作安全可逆。
- **归档分页**：「历史归档」默认每次显示最近 100 条，点击「显示更多」继续加载，不影响搜索与导出。
- **自动备份（v1.5）**：管理员在「数据导出」页可设置自动备份时间（默认**每周三 14:00**，可改星期与时分）与保留份数（默认 12 份，可改 1-100）。每次备份会在 `data/backups/` 生成一份**全库 JSON**（结构与「💾 备份全部数据」一致，可直接用「📥 还原数据」恢复）和一份**借用记录 CSV**（含归档，Excel 直接打开）。若计划时间电脑/服务没运行，会在**下次启动时自动补做一次**；「💾 立即备份」可随时手动备份，备份记录列表里可直接下载其中某一份。
- **数据防丢机制（v1.5，已加固）**：每次写入前系统在 `data/` 下留一份 `.bak` 快照，且 `data/` 下还有：
  - **`borrows.json.bak` 等 `.bak` 快照**：正常写入后与主文件内容一致；主文件被**删除 / 清空成 `[]` / 改小 / 截断 / 写成非法 JSON** 时，系统先隔离留证（`data/quarantine/`）再从 `.bak` 自动恢复并告警，**不会静默清空历史**；
  - **`data/quarantine/`**：被隔离的坏文件都留在这里（含时间戳），可人工检查或修复；
  - **`data/backups/`**：自动备份的全库 JSON + 借用记录 CSV（最后一道防线）；
  - **`data/.lock`**：单实例锁（见下条）。
  两份文件都无法恢复时，接口返回 **HTTP 503 明确报错**（具体原因写在 `server-err.log`），此时请用 `data/backups/` 里的备份 JSON 在「📥 还原数据」中恢复。恢复步骤见「六、常见问题」。
- **单实例保护（v1.5.1）**：同一份 `data` 目录**同时只能有一个服务实例**。第二个实例会**拒绝启动**并在 `server-err.log` 打印中文提示（实测两个实例同写同一份数据会静默丢记录，因此改为直接拒绝）；请先停止另一个实例再启动。若服务被强杀/断电留下 `data/.lock`，下次启动会**自动接管**（有告警），无需手工处理；仅当确认没有实例在运行时才手工删除该文件。
- **不要手工只改主文件**：由于上面的自动恢复，手工编辑 `data/*.json` 必须**连同同名 `.bak` 一起改**，否则会被自动恢复覆盖。要改数据请走界面或「📥 还原数据」。
- **登记校验更严（v1.5.1）**：物品数量必须是 **1-999 的整数**、单笔最多 **20 件**；不合法直接报错（不再静默改成 1 / 静默丢弃第 21 件）。还原数据时对伪造状态、畸形物品项会整体拒绝（400，一个字节都不写）。
- **已知局限**：列表接口会把签字与归还照片一并返回（单条大记录时响应可达数 MB，客户网络慢时较卡）；记录量很大时写入会变慢（1000 条约 26 秒）。建议定期导出归档并留意数据量。
- **操作日志（v1.5）**：管理员左侧「🧾 操作日志」页可查看成员每一步关键操作（时间 / 成员 / 账号(角色) / 操作 / 对象 / 详情 / IP），支持日期、成员、操作类型、关键词筛选与分页、导出 CSV；原始日志按天保存在 `data/logs/YYYY-MM-DD.jsonl`，默认保留 180 天自动清理。

## 六、常见问题

- **双击 start.bat 提示“服务已经在运行中”**：说明端口 10800 已被占用（服务已启动）。此时无需重复启动，脚本会自动打开 http://localhost:10800。若确需重启服务，先在任务管理器结束 node 进程，再运行 start.bat。
- **手机打不开页面**：① 确认同一局域网；② 执行上面的防火墙放行命令；③ 用 `ipconfig` 确认本机 IP 与二维码地址一致。
- **微信扫码提示“非微信官方网页”**：属正常提示（内网 HTTP），点「继续访问」即可打开。
- **忘记管理员密码**：删除 `data/users.json` 后重启服务，会自动恢复默认账号（admin/admin123）。
- **修改端口**：编辑 `server.js` 顶部 `const PORT = ...` 或运行前设置环境变量 `PORT`。
- **浏览器不弹超期通知**：请在浏览器地址栏允许本页面的通知权限。
- **怀疑丢了借用记录 / 记录"不见了"**：先看 `data/quarantine/` 有没有被隔离的坏文件，再看 `data/borrows.json.bak`。恢复办法：停掉服务 → 用 `data/borrows.json.bak` 覆盖 `data/borrows.json`（或从 `data/backups/` 里挑一份最近的备份 JSON，用「📥 还原数据」一键还原）→ 重新启动。日常建议：**保持自动备份开启**。
- **接口提示「数据文件损坏」（HTTP 503）**：说明 `borrows.json` / `users.json` / `inventory.json` 之一无法解析且没有可用备份。坏文件已自动复制到 `data/quarantine/` 留证，可人工修复后覆盖回 `data/`，或用最近一次备份还原。**注意：这是有意设计的"明确失败"，避免旧版那种把整库记录静默清空的情况。**
- **操作日志 / 自动备份文件在哪里**：日志按天保存在 `data/logs/YYYY-MM-DD.jsonl`（默认保留 180 天）；自动备份文件保存在 `data/backups/`（每份含 JSON + CSV，保留最近 12 次）。整目录拷走即可离线留存。
- **启动时提示「另一个服务实例正在使用同一份数据」**：同一份 `data` 目录已经有实例在运行（或残留了锁文件）。先停止另一个实例（双击「停止服务.bat」，或结束对应的 node 进程）；确认没有实例在运行时，删除 `data/.lock` 后重新启动即可。
- **手工改了 `data/borrows.json` 但重启后改动没了**：这是防丢保护——主文件被外部改动（删除/清空/改小/截断）时系统会从 `.bak` 恢复。要改数据请用「📥 还原数据」导入备份 JSON，或把同名 `.bak` 一起改。
- **提示「数量必须是 1-999 的整数」/「单笔最多登记 20 件物品」**：v1.5.1 起非法数量直接拒绝，不再悄悄改成 1 或丢掉第 21 件物品；按提示修正即可。
- **自动备份显示失败后不再自动重试**：备份失败也会推进计划时间（本周期不再尝试）。修好问题后请到「数据导出」页点一次「💾 立即备份」。
- **被隔离的坏文件想人工恢复**：`data/quarantine/` 里是按时间戳留证的坏文件；修好后**连同同名 `.bak` 一起**放回 `data/` 再启动服务。

## 七、账号与安全（v1.1）

- **修改自己的密码**：登录后点击右上角「修改密码」，输入当前密码和新密码即可；管理员也可在「用户管理」中为他人重置密码。
- **默认密码提醒**：仍在使用出厂默认密码（admin/admin123、operator*/123456）的账号登录后，工作台顶部会显示橙色提醒横幅，请尽快修改。
- **登录防暴力破解**：同一来源对同一用户名连续输错 8 次后，锁定 10 分钟。
- **账号停用/删除即时生效**：被停用或删除的账号，其已登录的会话会在下一次操作时立即失效。
- **借用时间校验**：登记时借用时间需在当前时间前后 7 天以内（支持补登），借期最长 90 天。
- **会话密钥**：首次启动自动生成并保存在 `data/session-secret`，也可通过环境变量 `SESSION_SECRET` 指定；请勿外泄该文件。

## 八、更新记录

### v1.5.1（2026-10，数据安全加固）

针对崩溃/断电与并发写入、备份与还原、输入校验与权限这三类场景做了专项对抗验证，修复的缺陷如下：

**静默丢记录的路径（全部已堵）**
- 数据文件被**删除**（杀软隔离 / 云同步搬走 / 误删）→ 旧行为是主文件与 `.bak` 被同时写成 `[]`（历史 100% 丢失、接口仍返回 200）；现在先查 `.bak` 并恢复 + 告警，绝不覆盖。
- 数据文件被**清空成 `[]`** → 隔离留证 + 从 `.bak` 恢复 + 告警（只针对「主文件 0 条而 `.bak` 有记录」这一窄情形，正常删除记录不受影响）。
- 数据文件被**换成合法但更短的数组**（例如只留前 3 条）→ 判据「主文件条数 < `.bak` 条数」即视为外部改小：隔离 + 从 `.bak` 恢复 + 告警。依据：正常写入的写后镜像保证两者一致，合法删除时两者同时变小。
- **`.bak` 为合法空数组 + 主文件损坏** → 旧行为是"恢复"成空库并生成一份**看似有效的空备份**；现在直接 **503 明确报错**，不写任何东西、不产生备份文件（`data/backups/` 的历史备份不受影响）。
- `.bak` 写入改为**原子**（`.tmp` + fsync + rename），不再出现半截 `.bak`。
- **两个实例同写同一份 `data`**（实测 40 并发下静默丢 7/107 条）→ 新增 `data/.lock` **单实例锁**：第二个实例在任何数据读写前被拒绝（退出码 1 + 中文提示），死锁自动接管。

**静默改值 / 让备份失效的问题（全部已修）**
- 登记数量 `0 / -1 / 1e9 / 2.5 / "abc"` 旧行为是静默改成 `1 / 1 / 999 / 2 / 1`，`items` 超 20 件静默丢件 → 现在一律 **400**（文案带物品名），落库值与提交值必须一致。
- `/api/restore` 旧行为接受伪造 `status`、`items:[null]` → 会让 `/api/export` 500 且**备份永久失败**；现在非法负载整体 **400**、一个字节都不写；同时导出/备份对畸形记录**容错**（跳过或按「（未知物品）」兜底），保证最后一道防线永远可用。
- 备份中途失败会留下"看似有效"的孤儿 JSON → 现在两份内容先在内存生成、写 `.tmp`、**全部成功后一起改名**，失败回滚零残留。
- 同秒残留 CSV 会让刚生成的 JSON 备份被 `keep` 清理掉 → json/csv **共用同一序号**；`keep` 以"组内是否有 JSON"为准，孤儿 CSV 直接清理。

**验证**：`/api/export` 三种 scope 与 v1.4 **逐字节一致**（sha256 相同）；原有借用业务流程回归全部通过；单实例锁（第二个实例被明确拒绝）、40 条并发提交（记录零丢失、单号不重复）、写入过程中强杀进程 10 轮（历史记录零丢失）、以及各类文件损坏/被篡改场景（隔离留证 + 自动恢复，或 503 明确报错）均验证通过。

**已知残余（有兜底，均非静默丢记录）**：① 主文件与 `.bak` 同时不可用（整个 `data/` 被删）→ 按首启初始化空库，只能靠 `data/backups/` 或外部留存的备份；② 外部把主文件换成"条数不少于 `.bak` 的不同内容"→ 会被接受（条数不减），需内容校验和/多代备份才能识别；③ 手工改主文件而不同步改 `.bak` 会被自动恢复覆盖（见「六、常见问题」）；④ 自动备份失败也推进 `lastRunAt`，本周期不再重试。

### v1.5（2026-10）

**修复：借用记录丢失（根因）**
- 根因：`lib/store.js` 的 `readJson()` 在**读失败 / JSON 解析失败时静默返回空数组**，而所有写接口都是「读整个数组 → 修改 → 写回整个数组」，于是**一次坏文件就会让下一次正常提交把全部历史记录永久覆盖**，接口还返回 `ok:true`，用户毫无察觉；同时 `writeJson()` 没有 `.bak`、没有 `fsync`。
- 现在的读：文件不存在才用默认值初始化；存在但为空 / 解析失败 / 结构不符时**绝不回退成空数据**——先把坏文件复制到 `data/quarantine/<名>.<时间戳>.corrupt` 留证，再尝试用 `.bak` 自动恢复；无可用备份则抛 `DataError`，接口返回 **HTTP 503** 并给出明确中文提示。
- 现在的写：写前留 `.bak` 快照 → 新内容写 `.tmp`、`fsync` 落盘 → 原子 `rename` 覆盖（Windows 下 `EPERM/EBUSY` 自动重试 3 次）→ 写后再镜像 `.bak`，保证 `.bak` 恒等于「最近一次成功写入」（恢复时不会丢最新一条）。
- 启动自检：清理遗留 `*.tmp`、打印三个数据文件的条数；`GET /api/stats` 新增 `total / lastBackupAt / lastBackupOk / dataHealth`，工作台概览新增「记录总数」「上次备份时间」，出现隔离文件或超过 14 天未备份时给出提醒。
- `/api/export` 输出与改造前**逐字节一致**（CSV 生成逻辑抽到 `lib/report.js` 共用，三种 scope 的 SHA256 校验通过）。
